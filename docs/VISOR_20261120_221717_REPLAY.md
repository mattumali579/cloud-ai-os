## 4. Root Cause Analysis & Corrections

### 1. Over-Strict Non-Index Extension in `classifyPose`
* **Root Cause**: The baseline classifier enforced `extendedNonIndexCount == 0`, counting any finger as extended if $d(\text{wrist}, \text{tip}) > 1.30 \times d(\text{wrist}, \text{mcp})$. In overhead glasses footage looking down at an arm pointing away, 2D foreshortening caused curled middle and ring fingers in a fist to project to $1.10\times\text{--}1.24\times$ the wrist-to-MCP distance. MediaPipe classified middle/ring fingers as "extended" on 94 pointing frames, incorrectly categorizing intentional pointing as `OPEN_PALM` or `HAND_VISIBLE` and suppressing the ray.
* **Correction**: Enforced index dominance and middle knuckle curvature:
  ```kotlin
  val indexDominant = dWristIndexTip > dWristMiddleTip * 1.10f && dWristIndexTip > dWristRingTip * 1.12f
  if (indexExtended && indexDominant && (midStraightness < 0.85f || dWristIndexTip > dWristMiddleTip * 1.18f)) {
      return HandPose.POINTING_INTENDED
  }
  ```

### 2. Angular Jitter in Forward Ray Direction
* **Root Cause**: Constructing the ray using the short distal segment ($\text{PIP} \rightarrow \text{TIP}$) introduced angular flutter when the distal joint flexed during camera motion.
* **Correction**: Switched to knuckle-to-tip vector ($\text{MCP} \rightarrow \text{TIP}$) as the primary ray vector, which provides a long, stable baseline along the finger axis, while strictly retaining the forward-dot-product check ($dir \cdot (\text{tip} - \text{wrist}) > 0$) to guarantee zero backward ray flips.

### 3. Viewport Coordinate Offset & Drift Correction
* **Root Cause**: On the S22 Ultra, the screen resolution is 1080x2316 while the camera preview is centered in a 1080x1440 letterbox. Running detection on the letterboxed image without applying the 438px vertical margin caused landmark offsets and drifting overlays.
* **Correction**: Vision inference runs directly on the 1080x1440 camera viewport. Coordinates are mapped to screen space via $y_{screen} = y_{cam} + 438$, eliminating drift and aligning landmarks directly with the wearer's real hand.

### 4. Handling Ambiguous Targets (`NO_TARGET`)
* When intentional pointing is active but the forward ray does not intersect any candidate object, the engine does not guess or fall back to center/nearest objects. It renders `NO_TARGET (AWAITING OBJECT)` clearly on the HUD badge.
